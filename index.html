Method

Pick how you want to update the live file. Both end with the same result — the portal reading a new data.xlsx from this repo.

Security note: your token lives only in this browser's local storage and is sent directly to GitHub's API over HTTPS — it never touches any third-party server. Scope it as narrowly as GitHub allows (ideally: this one repository, Contents → read and write, nothing else) and revoke it any time from GitHub's Developer Settings if you suspect it leaked.
  1. Go to your repository on github.com.
  2. Open data.xlsx in the file list, then click the pencil (edit) icon, or click Add file → Upload files and drop in your new spreadsheet with the exact same name, data.xlsx.
  3. Scroll down and click Commit changes directly on the default branch.
  4. Wait for GitHub Pages to redeploy (see timing note below), then refresh the portal.
Use this path any time you'd rather not create a token — it takes about the same two minutes and needs no setup in the portal at all.

What happens after you commit

GitHub Pages is a static host, so a new commit doesn't appear on the live site instantly.

  • Typical propagation: 1–3 minutes after the commit lands.
  • This portal appends a cache-busting timestamp to every data fetch, so once GitHub has redeployed, you'll see the new file on the very next refresh — no browser cache clearing needed.
  • Use Refresh now in the top bar, or just wait for the automatic 5-minute refresh.
If it's been over 5 minutes and the data still looks old, check the Actions tab on your GitHub repo — that's where a stuck Pages build will show up.

Generating a scoped token

  1. On GitHub: Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token.
  2. Set Resource owner to your account, and under Repository access choose Only select repositories → pick this one repo.
  3. Under Permissions → Repository permissions, set Contents to Read and write. Leave everything else as No access.
  4. Generate the token, copy it once, and paste it into the field on the left.

    Adding, removing or changing a manager

    Accounts are a plain list near the top of this HTML file — there's no separate database. Edit the AREA_MANAGERS array, save, and re-commit the file (or re-upload it) the same way you update data.

    const AREA_MANAGERS = [ { username: "irfan", password: "ChangeMe1!", displayName: "Irfan" }, { username: "saurabh", password: "ChangeMe2!", displayName: "Saurabh" }, // … ];

    displayName must match the text in the Area Managers column of data.xlsx exactly (spelling, not case) — that's what isolates each manager's view.
